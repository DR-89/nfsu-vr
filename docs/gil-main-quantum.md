# Эксперимент: минимальный квант основного потока перед PREEMPT

Android-свойство `debug.nfsu.gil_quantum_us` задаёт минимальное монотонное
wall-время после получения GIL, в течение которого основной игровой поток
игнорирует запрос RECOMP_PREEMPT. Это не sleep и не гарантированное CPU-время.
Вытеснение Android может израсходовать квант без работы гостевого кода.

Начальный эксперимент — 100 микросекунд. По умолчанию 0: прежнее поведение.
Разрешено 0..1000 мкс; неверное значение отмечается в логе и означает 0.
Значение читается при старте процесса. Startup-маркер эффективного значения:

```text
[THREAD] main PREEMPT quantum=100 us
```

Ограничение действует только на основной поток, помеченный
`xbox_gil_mark_main`. Для рабочих потоков PREEMPT остаётся прежним.
Каждое повторное получение GIL начинает новый квант.
Блокирующие kernel calls и RECOMP_SPIN_HINT по-прежнему отпускают GIL.
Guards ISR/DPC не изменены. Удерживаемый запрос вытеснения не сбрасывается:
после окончания кванта следующий PREEMPT снова может передать GIL.
Запросы других потоков, включая аудио и обработчики, могут быть отложены
этим квантом; отдельно проверить звук, события и сохранения.

После самостоятельной сборки и установки одного APK:

```bash
adb shell setprop debug.nfsu.diagnostics 0
adb shell setprop debug.nfsu.perf 1
adb shell setprop debug.nfsu.gil_eager 1
adb shell setprop debug.nfsu.gil_quantum_us 100
adb shell am force-stop org.nfsu.android
adb shell am start -n org.nfsu.android/.LauncherActivity
```

Открыть прежнюю проблемную сцену, повторить тормоза 30–60 секунд и забрать
`nfsu1.log`. Для контрольного запуска изменить значение на 0 и полностью
перезапустить. Предпочтительное сравнение: 0 → 100 → 0 с одинаковыми сценой,
прогревом и длительностью. Сохранить логи отдельно до каждого перезапуска.
Оценивать FPS и preempt_wait/preempt_total; затем проверить звук и гонку.

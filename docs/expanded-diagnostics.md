# Расширенная диагностика Android, версия 2

Диагностика не требует ADB во время игры и не подключает debugger.
Звук, файлы и ожидания продолжают выполнять исходные операции.
Синхронный сбор метаданных имеет ненулевую стоимость и может менять тайминги.

## Включение и сравнение производительности

Подробный сбор по умолчанию выключен: callbacks истории возвращаются до
измерения времени и захвата общего mutex; аудиоснимки и периодический
input-log также отключены. Проверки повреждённых audio links, сообщения об
ошибках, crash-handler и базовый журнал запуска остаются.

Счётчики `[PERF5]` включаются отдельно через `debug.nfsu.perf`; в текущей
диагностической версии они включены по умолчанию. Подробности и формат —
в [performance-counters.md](performance-counters.md).

Один APK поддерживает оба режима. Перед запуском игры:

```bash
adb shell setprop debug.nfsu.diagnostics 1  # подробная диагностика
adb shell setprop debug.nfsu.diagnostics 0  # обычный режим
```

Свойство читается только при старте native-игры. После изменения полностью
перезапустить приложение; `[ANDROID] detailed diagnostics=0/1` в `nfsu1.log`
подтверждает выбранный режим. Переключатель не меняет GIL, APU и Vulkan.
Сравнивать одинаковую сцену и настройки после прогрева, по три отрезка
30 секунд на режим; не сравнивать показатели главного меню с гонкой.

## Файлы

В `/sdcard/Android/data/org.nfsu.android/files/`:

- `nfsu1.log` — текущий запуск;
- `nfsu1.previous.log` — предыдущий запуск. При каждом старте текущий
  переименовывается в previous; сохраняются два последних запуска.

После сбоя лучше забрать оба файла. При повторных стартах более старый лог
заменяется. Шумные покадровые сообщения GPU отключены через `RECOMP_QUIET=1`;
ошибки и диагностические сообщения сохраняются.

Дополнительно Android сохраняет общий `logs/all.log` и отдельные файлы
подсистем, включая `runtime.log`, `audio.log`, `files.log` и `input.log`.
Каталог остаётся на месте: zlog дописывает текущие файлы и ротирует их
по размеру, добавляя дату и номер к именам архивов. Настройки `nfsu1x_env.txt` читаются из корня
каталога приложения. Подробности: [Android logging](android-logging.md).

## Содержание

- `[AUDTRACE]`: прогресс аудио-update и состояние остановки звука, как раньше.
- `[FILEOPEN]` / `[FILEOPENFAIL]`: путь, guest handle token, флаги открытия,
  либо статус ошибки. Позволяют связать чтения с музыкальным файлом или сейвом.
- `[RUNTIME]`: каждые 5 секунд сводка, число сохранённых событий,
  текущих ожиданий и потерянных/перезаписанных событий.
- `[HISTORY]`: ограниченная история 128 событий. `t` — monotonic milliseconds,
  `tid` — native Linux TID. `op` печатается в hex. Обычные значения — Xbox
  kernel ordinal: 219 read, 236 write, 190 create, 198 flush, 187 close,
  226 set-information. Все завершённые файловые операции, ошибки и операции
  длительностью не менее 100 ms сохраняются; быстрые успешные locks/waits
  в историю не попадают, но учитываются как pending, пока не вернулись.
- `[WAITSTATE]`: верхнее наблюдаемое незавершённое ожидание каждого потока,
  caller и аргументы. Ожидание может быть нормальным (idle worker); это
  снимок состояния, а не автоматический диагноз deadlock.
- `op=80000001` / `ordinal=2147483649`: ожидание GIL; args — младшая и старшая
  части своего ticket, младшая часть обслуживаемого ticket, индекс priority.
- `op=400000DB` / `400000EC`: результат read/write в IO_STATUS_BLOCK;
  args — handle token, offset low/high, фактические bytes; result — статус.
  Offset `FFFFFFFF,FFFFFFFF` означает последовательную операцию, фактическая
  позиция fd не измеряется. Обычный read/write event содержит handle, buffer,
  requested length, адрес offset-параметра.
- `op=001E6921` / `801E6921`: состояние voice-list до/после обработки голоса;
  `op=001E2880` / `801E2880`: до/после unlink. Args — node, next, prev, parent.
  Снятые после unlink ссылки не проверяются на reciprocal-связность:
  удалённый узел не обязан оставаться связанным.
- `[VOICE-LINK]`: нарушение связности наблюдено до оригинальной операции.
  Печатаются обе ссылки и, для voice, channel/count/status/owner; перед
  продолжением оригинального кода принудительно выводится retained history.
  Запись обозначает первое наблюдение на этих границах, а не доказанную
  первую запись повреждённых байт во всём игровом коде.
- `[NATIVE]`: при старте база библиотеки; при crash — PC, LR, SP, FP и
  x0..x30 из настоящего ARM64 ucontext. `pc_offset` применим к библиотеке игры,
  если PC находится в ней. Guest-регистры отдельно могут быть последним
  опубликованным TLS-состоянием; native PC точно указывает faulting instruction.

Все наблюдаемые записи делаются без остановки потоков. Есть лимит 32 потока
и 8 вложенных наблюдаемых вызовов; превышения отражаются в `dropped`.
Проверки links читают только проверенные диапазоны guest RAM. Эти снимки
не охватывают каждую запись памяти и не заменяют полный native stack unwind.
Падения до установки crash-handler или принудительное завершение Android
могут не дать `[NATIVE]`; для них нужен Android logcat/ANR-отчёт.

## Проверка

Host-тест `tests/android_diagnostics.c`: выключенный режим при уже захваченном
mutex (callbacks не должны блокироваться или сохранять события), 8 параллельных производителей,
вложенные вызовы, 16000 событий, оборот ring-buffer, переполнение вложенности.
Запуск:

```bash
cc -Wall -Wextra -Werror -pthread tests/android_diagnostics.c -o /tmp/nfsu-diagnostics-test
/tmp/nfsu-diagnostics-test
```

Это проверка диагностического хранилища; она не доказывает правильность
игры, звука или отсутствия device-регрессии. Для расшифровки native PC
нужна unstripped `libnfsu2_recomp.so` именно этого APK, а не следующей сборки.

# Сравнение DirectSound с Xbox XBE

Сравнение выполнено 2026-10-14 для `game/Need For Speed Underground/default.xbe`
и C из `android/app/build/generated/recomp/` текущей диагностической сборки.

## Подлинность дизассемблирования

Байты каждой инструкции в `recomp-analysis/disasm/asm/DSOUND.asm` проверены
непосредственно по XBE с отображением VA → raw offset секции DSOUND из
`recomp-analysis/xbe-analysis.json`. Пропусков между инструкциями нет.

| Функция | Диапазон (конец исключён) | Инструкции | Байты |
|---|---|---:|---:|
| `sub_001E5423` | `001E5423..001E5473` | 23 | 80 |
| `sub_001E6921` | `001E6921..001E6AFD` | 147 | 476 |

Все 556 байт совпали. Это проверка соответствия дизассемблирования бинарнику,
а не доказательство динамической эквивалентности C.

## Проверенные операции в C

`sub_001E5423` находится в `recomp_0049.c`, `sub_001E6921` — в `recomp_0050.c`.
При статической сверке тел ошибок в перечисленных операциях не обнаружено:

- Проверка voice index `< 256`, состояния объекта по `+0x84`, аппаратного
  voice flag `0x800000`, таблицы объектов `+0x88 + index*4`.
- Чтение числа voices (`byte +0x64`) и индекса (`word +0xA + count*2`).
- Проверка linked-list на self-pointer `object+0x4C`, передача `ecx` и
  аргумента `1` в `sub_001E6921`, стековый возврат `ret 4`.
- В `sub_001E6921`: построение sentinel `parent + channel*8 + 0x488`,
  загрузка соседей `object+0x50` и `object+0x4C`, проверки на sentinel.
- Преобразование соседнего list-node в объект вычитанием `0x4C`, ширина
  чтений byte/word, unsigned-переходы цикла, сдвиги voice index на 7.
- Изменения аппаратной цепочки, вызов unlink `sub_001E2880(object+0x4C)`,
  сброс channel byte в `0xFF`, проверка `0x8000`, добавление в список
  `parent+0x4A0` и постановка DPC. Сохранение/восстановление регистров и
  явные push/pop соответствуют оригинальному телу.

Доступы `MMIO_RD*` добавлены рекомпилятором: аппаратные адреса передаются
модели устройства, RAM — обычным guest-accessors. `XBOX_PTR` приводит адрес
к `uint32_t`, сохраняя 32-битную арифметику Xbox. Корректность модели APU
этим сравнением не проверена.

## Подозреваемый путь ошибки

Оригинальные инструкции:

```asm
001E6969  mov   eax, [esi+0x50]         ; соседний list-node
001E696C  cmp   ecx, eax                ; ecx = sentinel
001E6971  jne   001E697C
001E697C  lea   edi, [eax-0x4C]         ; объект из list-node
001E697F  movzx eax, byte [edi+0x64]    ; число voices
001E6983  movzx eax, word [edi+eax*2+0xA]
```

Соответствующий C:

```c
eax = MMIO_RD32(esi + 0x50);
/* сравнение с sentinel и переход */
edi = eax - 0x4C;
eax = ZX8(MMIO_RD8(edi + 0x64));
eax = ZX16(MMIO_RD16(edi + eax * 2 + 0xA));
```

Если соседний node равен нулю, `edi=0xFFFFFFB4`. Первое чтение обращается
к VA `0x18` после 32-битного переполнения. Если прочитанный там byte равен
нулю, второе чтение получает VA `0xFFFFFFBE`: тот же адрес, что в присланном
логе SIGSEGV. Это условное воспроизведение арифметики, не установленная
faulting instruction: PC и реальные значения этих локальных регистров
в логе не сохранены. TLS-регистры crash-report могут быть последним
опубликованным состоянием, когда generated code держит регистры в C-local.

В оригинале также нет проверки соседнего node на NULL: sentinel-список
должен иметь корректные ссылки. Добавить NULL-check в эту функцию — значит
изменить поведение Xbox-кода, а не исправить найденную ошибку трансляции.

## Граница вывода и дальнейшая проверка

На исследованном пути прямого расхождения C и инструкций Xbox не найдено.
Это не исключает ошибку в других функциях, MMIO, ABI/macro реализации
или порядке выполнения прерываний и потоков. Runtime добавляет
`RECOMP_PREEMPT` и передаёт исполнение host/kernel, чего в XBE нет.

Следует фиксировать объект, sentinel и обе ссылки перед входом в
`sub_001E6921`, затем найти первое изменение, нарушившее связи. Отдельно
проверить аппаратные voice-события, их доставку ISR/DPC и время жизни
объекта. Ни конкретный источник нарушения списка, ни исправление пока
не установлены. Игра для этого статического сравнения не запускалась.

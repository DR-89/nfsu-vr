# Адресная передача GIL на Android

Освобождение GIL теперь сигналит только условной переменной ожидающего
следующего билета. Порядок FIFO, таймаут ожидания 1 мс, eager-запросы и
правила ISR/DPC сохранены. На остальных платформах прежняя реализация.

Ожидающий добавляет узел в очередь под `s_gil_cs`, затем атомарно отпускает
эту же блокировку при ожидании. Освобождающий сигналит голову под `s_gil_cs`.
После любого пробуждения владелец проверяет номер билета повторно, поэтому
ложный сигнал или таймаут не позволяют обойти очередь. Узел и его условная
переменная живут на стеке до получения билета; выделения памяти в куче нет.
Удаление и уничтожение условной переменной происходят под той же блокировкой.

Startup-маркер новой версии:

```text
[THREAD] GIL handoff: targeted FIFO wake, 1 ms preemption timeout
```

## Проверка

Host-тест включает настоящую реализацию GIL из kernel_bridge.c и выбирает
Android-ветку handoff, используя POSIX Win32-compat primitives:

```bash
cc -O1 -ffunction-sections -fdata-sections -Ixboxrecomp/src \
  -Ixboxrecomp/src/kernel tests/gil_handoff.c \
  xboxrecomp/src/platform/win32_compat.c -Wl,--gc-sections -pthread -lm \
  -o /tmp/nfsu-gil-handoff-test
timeout 30s /tmp/nfsu-gil-handoff-test 0
timeout 30s /tmp/nfsu-gil-handoff-test 1
```

Оба режима прошли: восемь упорядоченных ожидающих, сигнал только голове,
ложное пробуждение последнего билета, таймауты с запросом вытеснения,
вложенные входы, suspend/resume и 24000 конкурентных входов без нарушения
взаимного исключения и с полной очисткой очереди.

Тест также включает настоящие счётчики PERF5: искусственная задержка 2 мс
после передачи билета, но до сигнала должна попасть в `gil_handoff`.
Для каждого упорядоченного ожидающего проверяются по одному событию
`gil_queue` и `gil_handoff`. Это проверяет границы измерения, а не скорость Poco.

Android APK не собирался и не запускался. После самостоятельной сборки
повторить проблемный участок с `diagnostics=0`, `gil_eager=1`, `perf=1`.
Забрать полный `nfsu1.log` по инструкции в performance-counters.md.
Сравнивать на одинаковой сцене прежде всего FPS и долю gil_wait у main.
Уменьшение числа разбудившихся потоков не является доказательством прироста
FPS на Poco; проверить также звук, гонку, смену гонки и автосохранение.
